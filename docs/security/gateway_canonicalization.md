# Gateway Canonicalization Spec

This repository treats Python, Go, and Node gateway-side validation as one protocol.
The canonical request payload is the only source of truth for:

- `gateway_meta.request_hash`
- `gateway_signature`

## Input

The input is the full gateway envelope or sidecar request body.
Validators must canonicalize the exact payload they receive. They must not rebuild a smaller derived map first.

## Canonicalization Rules

Before serialization:

- remove top-level `gateway_signature`
- remove `gateway_meta.request_hash`
- keep every other field unchanged

Serialization rules:

- JSON object keys are recursively sorted
- array order is preserved
- UTF-8 encoding
- no extra whitespace
- escaping matches Python `json.dumps(..., ensure_ascii=False, sort_keys=True, separators=(",", ":"))`
- HTML-style escaping is not allowed during canonical serialization

## Derived Values

- `request_hash = sha256(canonical_bytes).hexdigest()`
- `gateway_signature = HMAC-SHA256(sha256(master_key).digest(), canonical_text_utf8).hexdigest()`

This matches `zen_claw.utils.crypto.sign_data(...)`.

## Golden Fixtures

Cross-language fixtures live in:

- `tests/fixtures/gateway_canonicalization_cases.json`
- `tests/fixtures/gateway_canonicalization_golden.json`

The golden file is generated by:

- `E:\nano-claw-public\.venv\Scripts\python.exe scripts\generate_gateway_canonicalization_fixtures.py`

Reference helpers live in:

- `zen_claw/security_context.py`

Sidecar implementations must produce the same canonical text, request hash, and signature as the Python reference helpers for every golden fixture.
